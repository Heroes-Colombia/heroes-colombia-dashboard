# Firebase Schema V2 - Heroes Colombia

**Version:** 2.0
**Last Updated:** 2025-01-15
**Status:** Production Ready

---

## Overview

This document defines the **authoritative Firebase schema** for Heroes Colombia platform. This schema is optimized for:
- Website (trial sign-ups and marketing)
- Dashboard (business management)
- Flutter App (consumer browsing and future redemptions)

**Migration Status:** V1 → V2 requires manual migration (1 production client to migrate)

---

## Design Principles

1. **snake_case for collections** (Firebase convention)
2. **camelCase for document fields** (but maintaining snake_case for legacy compatibility where needed)
3. **Subcollections for one-to-many relationships** (locations, team members)
4. **Denormalization for read performance** (embed frequently accessed data)
5. **Support future features** (schema ready for Phase 2/3 features)

---

## Collections Overview

```
users/                          # All users (consumers + business team)
businesses/                     # Business profiles
  └─ locations/                 # Subcollection: business locations
subscriptions/                  # Business plan subscriptions
promotions/                     # Business promotions (renamed from advertisements)
business_categories/            # Category definitions
redemptions/                    # Promotion redemptions (future)
analytics_events/               # Analytics tracking (future)
```

## Collection: `users`

**Purpose:** All platform users (military personnel consumers + business team members)

**Document ID:** Firebase Auth UID

**Fields:**

```typescript
{
  // Core Identity
  uid: string
  email: string
  user_type: "consumer" | "business_team"  // Determines which fields apply
  status: "pending" | "active" | "rejected" | "suspended"
  verified: boolean
  created_at: Timestamp
  updated_at: Timestamp

  // Consumer Fields (military personnel)
  first_name?: string
  second_name?: string
  first_last_name?: string
  second_last_name?: string
  identification_card?: string  // Cédula
  license?: string              // Military license number
  rank?: string                 // Format: "BRANCH_CATEGORY_RANK"
  phone?: string
  city?: string
  favourite_businesses?: string[]  // Array of business IDs
  device_notification_token?: string

  // Business Team Fields
  business_roles?: [{
    business_id: string           // Reference to businesses collection
    role: "owner" | "manager" | "staff"
    permissions: string[]         // ["manage_promotions", "view_analytics", "process_redemptions"]
    invited_by: string            // User ID who sent invitation
    invited_at: Timestamp
    joined_at: Timestamp
    is_active: boolean
  }]
}
```

**Indexes:**
- `email` (unique, enforced by Firebase Auth)
- `user_type` (for filtering)
- `status` (for admin dashboard)
- `business_roles.business_id` (for team queries)

**Security Rules:**
```javascript
// Users can read their own document
allow read: if request.auth.uid == resource.id;

// Users can update their own profile (except role/status fields)
allow update: if request.auth.uid == resource.id
  && !request.resource.data.diff(resource.data).affectedKeys().hasAny(['user_type', 'status', 'verified', 'business_roles']);

// Admins can read/write all
allow read, write: if request.auth.token.admin == true;
```

## Collection: `businesses`

**Purpose:** Business profiles and master data

**Document ID:** Auto-generated by Firestore

**Fields:**

```typescript
{
  // Basic Information
  name: string
  identification: string        // NIT
  email: string                 // Business contact email
  phone_number: string          // Business contact phone
  description?: string
  website?: string              // Business website (both physical and online have this)
  featured_image?: string       // Main business image (not per location)

  // Business Type
  type: "physical" | "online" | "hybrid"  // ⚠️ NEW: Determines if has physical locations

  // Owner Information
  owner_name: string
  owner_uid: string             // Reference to users collection

  // Primary Location (for physical/hybrid businesses only)
  // This is duplicated from the primary location subcollection for geospatial queries
  // Online-only businesses: these fields are null or default values
  address?: string              // null for online-only
  location?: GeoPoint           // null for online-only
  geo_hash?: {
    geohash: string
    geopoint: GeoPoint
  }

  // Categories
  categories: string[]          // Simple IDs like ["tecnologia", "restaurante"] matching category_id in business_categories

  // Status & Features
  status: "pending" | "active" | "inactive" | "suspended" | "rejected"
  featured: boolean             // Enterprise plan feature

  // Plan & Subscription
  plan: "gratis" | "basico" | "pro" | "enterprise"
  subscription_id?: string      // Reference to subscriptions collection
  trial_end_date?: Timestamp    // Set by website after trial payment
  early_bird_applied?: boolean  // True if selected plan before Jan 15, 2026

  // Extra Promotions (Pay-per-promotion for plans that hit limit)
  extra_promotions_purchased?: number   // ⚠️ NEW: Extra promotions bought beyond plan limit
  extra_promotions_active?: number      // ⚠️ NEW: Currently active extra promotions

  // Metadata
  created_at: Timestamp
  updated_at: Timestamp
  created_by: "website" | "dashboard" | "admin"  // Track origin

  // Legacy fields (keep for migration compatibility)
  reviews?: any[]               // Will be moved to separate collection in Phase 3
  payment_methods?: any[]       // Deprecated, use subscriptions collection
}
```

**Indexes:**
- `status` + `plan` (for admin filtering)
- `owner_uid` (for owner's business list)
- `categories` (for category filtering in app)
- `location` (geospatial queries)
- `featured` + `status` (for featured businesses)

**Security Rules:**
```javascript
// Public read for active businesses
allow read: if resource.data.status == 'active';

// Owner can read/write their business
allow read, write: if request.auth.uid == resource.data.owner_uid;

// Team members can read
allow read: if request.auth.uid in getBusinessTeamMembers(resource.id);

// Admins can do everything
allow read, write: if request.auth.token.admin == true;
```

## Subcollection: `businesses/{businessId}/locations`

**Purpose:** Multiple physical/online locations per business

**Document ID:** Auto-generated by Firestore

**Fields:**

```typescript
{
  // Location Identity
  name: string                  // "Restaurante Juan - Chapinero" or "Juan Online Store"
  is_primary: boolean           // Exactly one location must be primary
  type: "physical" | "online"

  // Contact Information (ALL locations have these)
  phone?: string                // Direct phone for this location
  email?: string                // Direct email for this location
  website?: string              // Website (especially for online locations)

  // Physical Location Fields (only if type = "physical")
  address?: string
  location?: GeoPoint
  geo_hash?: {
    geohash: string
    geopoint: GeoPoint
  }
  business_hours?: {
    monday: { open: string, close: string, is_open: boolean }
    tuesday: { open: string, close: string, is_open: boolean }
    wednesday: { open: string, close: string, is_open: boolean }
    thursday: { open: string, close: string, is_open: boolean }
    friday: { open: string, close: string, is_open: boolean }
    saturday: { open: string, close: string, is_open: boolean }
    sunday: { open: string, close: string, is_open: boolean }
  }

  // Online Location Fields (only if type = "online")
  delivery_zones?: string[]     // Array of city/area names ["Bogotá", "Medellín"]
  delivery_type?: "national" | "regional" | "local"
  whatsapp?: string             // WhatsApp contact for online orders

  // Status & Metadata
  status: "active" | "inactive"
  created_at: Timestamp
  updated_at: Timestamp
}
```

**Constraints:**
- Exactly ONE location must have `is_primary: true`
- Primary location's address/coordinates are synced to parent business document
- Plan limits enforce max locations (Gratis: 1, Básico: 3, Pro: 10, Enterprise: unlimited)
- Online locations have `location: null` and `address: null`

**Indexes:**
- `is_primary` (to find primary location)
- `status` (for active location queries)
- `type` (to filter physical vs online)
- `location` (geospatial queries for nearby physical locations - collection group index)

**Collection Group Index (for Flutter App - Option B):**
- Create collection group index on `locations` with `location` field for geospatial queries across ALL businesses

## Collection: `subscriptions`

**Purpose:** Track business subscription status and plan history

**Document ID:** Auto-generated by Firestore

**Fields:**

```typescript
{
  // Subscription Identity
  business_id: string           // Reference to businesses collection

  // Plan Details
  plan: "gratis" | "basico" | "pro" | "enterprise"
  billing_cycle: "monthly" | "annual"
  status: "trial" | "active" | "past_due" | "canceled" | "expired"

  // Timing
  current_period_start: Timestamp
  current_period_end: Timestamp
  trial_end_date?: Timestamp    // Only for trial subscriptions

  // Pricing (stored for historical record)
  amount: number                // In COP, includes IVA
  currency: "COP"
  early_bird_applied: boolean
  discount_applied?: number     // Percentage (e.g., 50 for early bird)

  // Payment Integration
  mercadopago_subscription_id?: string
  payment_method_id?: string
  last_payment_date?: Timestamp
  next_billing_date?: Timestamp

  // Metadata
  created_at: Timestamp
  updated_at: Timestamp
  created_by: "website" | "dashboard"

  // Historical tracking
  previous_plan?: string        // For upgrade/downgrade tracking
  changed_from_trial?: boolean
}
```

**Indexes:**
- `business_id` (to find business subscription)
- `status` (for billing operations)
- `next_billing_date` (for billing reminders)
- `plan` (for analytics)

**Security Rules:**
```javascript
// Business owner can read their subscription
allow read: if getBusinessOwner(resource.data.business_id) == request.auth.uid;

// Only dashboard backend can write
allow write: if request.auth.token.dashboard_admin == true;
```

**Business Rules:**
- Only ONE active subscription per business
- When plan changes, create new subscription document (keep history)
- Trial → Paid transition creates new subscription record

## Collection: `promotions`

**Purpose:** Business promotions and offers (renamed from `advertisements`)

**Document ID:** Auto-generated by Firestore

**Fields:**

```typescript
{
  // Promotion Identity
  business_id: string           // Reference to businesses collection
  title: string
  description: string
  instructions: string          // Redemption instructions
  featured_image: string

  // Discount Details
  percentage: number            // Discount percentage (0-100)
  type?: "percentage" | "fixed" | "bogo" | "free_shipping"  // Future enhancement

  // Targeting
  location_ids: string[]        // Array of location IDs (empty = all locations)
  target_ranks?: string[]       // Future: specific military ranks
  target_cities?: string[]      // Future: geographic targeting

  // Timing
  start_date?: Timestamp        // Future feature
  expired_at: Timestamp         // End date

  // Limits
  max_redemptions?: number      // Future: total redemption limit
  max_per_user?: number         // Future: per-user limit
  current_redemptions?: number  // Future: counter

  // Status & Features
  status: "draft" | "pending" | "active" | "inactive" | "expired"
  is_featured: boolean          // Enterprise plan feature
  featured_priority?: number    // Sort order for featured promotions

  // Metadata
  created_at: Timestamp
  updated_at: Timestamp
  created_by: string            // User ID who created

  // Analytics (denormalized for performance)
  views_count?: number
  saves_count?: number
  redemptions_count?: number
}
```

**Indexes:**
- `business_id` + `status` (for business's active promotions)
- `status` + `expired_at` (for finding active promotions)
- `is_featured` + `status` (for featured promotions)
- `location_ids` (for location-specific promotions)

**Security Rules:**
```javascript
// Public read for active promotions
allow read: if resource.data.status == 'active';

// Business owner/team can read/write their promotions
allow read, write: if isBusinessTeamMember(resource.data.business_id, request.auth.uid);

// Admins can do everything
allow read, write: if request.auth.token.admin == true;
```

**Business Logic:**
- Count active promotions per business to enforce plan limits
- Draft promotions don't count toward limits
- Featured promotions only for Enterprise plan

## Collection: `analytics_events` (Phase 2 - Implemented in Flutter Week 2)

**Purpose:** Event tracking for detailed analytics (enables Basic & Advanced analytics features sold to businesses)

**Document ID:** Auto-generated by Firestore

**Fields:**

```typescript
{
  // Event Classification
  event_type: "impression" | "view" | "save" | "share" | "click" | "redemption"
  entity_type: "business" | "promotion" | "location"
  entity_id: string             // Business/Promotion/Location ID

  // User Context
  user_id?: string              // Consumer user ID (if logged in)
  user_type?: "consumer" | "anonymous"
  user_rank?: string            // Military rank (for demographics)
  user_city?: string            // User city (for demographics)

  // Location Tracking (for per-location analytics - Pro+ feature)
  business_id?: string          // Parent business ID
  location_id?: string          // Specific location where event occurred

  // Session & Source
  session_id?: string           // User session ID
  timestamp: Timestamp          // When event occurred

  // Additional Context
  metadata?: {
    source: "mobile_app" | "web_app"
    screen?: string             // Which screen/page
    referrer?: string           // How they got there
    device?: string             // Device type
    user_location?: GeoPoint    // User's location when event fired
  }
}
```

**Indexes:**
- `business_id` + `timestamp` (for business analytics)
- `location_id` + `timestamp` (for per-location analytics - Pro+ feature)
- `user_id` + `timestamp` (for user activity tracking)
- `event_type` + `entity_type` (for filtering)

**Security Rules:**
```javascript
// Only authenticated users can write events
allow write: if request.auth != null;

// Business owners can read their own events
allow read: if get(/databases/$(database)/documents/businesses/$(businessId)).data.owner_uid == request.auth.uid;

// Admins can read all
allow read: if request.auth.token.admin == true;
```

**Usage for Analytics Tiers:**

**Basic Analytics (Gratis & Básico):**
- Count events by `event_type` for entire business
- Simple metrics: total impressions, views, saves, redemptions

**Advanced Analytics (Pro & Enterprise):**
- Aggregate by `location_id` for per-location metrics
- User demographics from `user_rank` and `user_city`
- Conversion funnels (impression → view → save → redemption)
- Time-series analysis with `timestamp`

**Enterprise Analytics:**
- All of above + cohort analysis
- Retention tracking
- Advanced segmentation

## Schema Validation Rules

### Business Creation
- Must have at least 1 location (primary)
- Must have valid owner_uid
- Must have at least 1 category_id
- Status starts as "pending"

### Promotion Creation
- Must belong to existing business
- Must have expired_at > current time
- Count toward plan limits only if status = "active"
- location_ids must exist in business's locations subcollection

### Subscription Rules
- Only 1 active subscription per business
- Trial businesses have plan="enterprise" until trial_end_date
- Status must update based on payment events

---

## Performance Considerations

### Denormalized Data (for read performance)
- Business document includes primary location (duplicate)
- Promotion includes analytics counts
- Category includes business_count

### Indexes Required
- All collections: created_at DESC (for pagination)
- Geospatial: location fields
- Plan enforcement: status + plan combinations

### Query Patterns
```javascript
// Find nearby businesses (Flutter app)
// Uses geo_hash for efficient geospatial queries

// Find business's active promotions (Dashboard)
promotions
  .where('business_id', '==', businessId)
  .where('status', '==', 'active')
  .orderBy('created_at', 'desc')

// Find featured promotions (Flutter app)
promotions
  .where('is_featured', '==', true)
  .where('status', '==', 'active')
  .orderBy('featured_priority', 'asc')
```
